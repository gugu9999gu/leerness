# Scoped harness reading

Leerness-generated instructions distinguish the main session owner from delegated workers and reviewers. The owner loads current context and active rules, registers the work, records shared state and closes the session. Delegates reuse that assignment and report their findings and evidence. They do not register the same task again or close the parent session.

The generated `AGENTS.md` required-behavior lines for `handoff`, shared progress writeback and `session close` now name the main session owner explicitly in both authoring languages. An older Korean installation may still contain the three unqualified generated lines below its newer scoped heading. On migration, those exact lines are retired from the active managed `Required behavior` section only when the archive contains the byte-identical pre-migration `AGENTS.md`. Edited lines, other sections and previously preserved text remain for review. This changes instructions, not agent permissions or the evidence required from a reviewer.

When an older installation is migrated, the exact generated blanket-reading blocks in `AGENTS.md` and the old owner-wide commands in `CLAUDE.md`, Cursor and Copilot instructions are retired only if the migration archive contains the byte-identical original. Edited instructions and previously preserved project text remain available for review. `migrate --no-env` skips `.env` and `.env.example` generation or merge; the separate migration of existing nonsecret Leerness settings from `.env` still runs. A dry run now names `migrate` as the apply command. Review the resulting instruction diff before updating an actively used project.

Before delegating, provide the task ID, role, scope, allowed files, current rule text with IDs and source revision/check time, relevant decisions, fixed acceptance criteria, and source/evidence references. A count of rules or a claim that they were read is insufficient. Missing, stale or contradictory constraints require checking the relevant original before dependent work. Explicit user and project instructions still apply.

Generated routing lists are an index to relevant sections. Start with named current files and exact task/rule IDs or headings. Narrow a truncated search rather than printing the entire history in chunks. Expand the scope when a dependency, missing evidence or relevant regression requires it. Never remove required constraints just to meet a size target.

Reviewers still inspect the source, changes and execution evidence independently. Keep the same review ID and fixed criteria under the [review feedback protocol](review-feedback.md). Reducing duplicate onboarding does not authorize weaker verification, new criteria or a different reviewer identity. Reuse scan/test evidence only when its relevant state and scope remain valid; changed inputs and unresolved failures require appropriate checks.

`handoff --compact` is navigation, not full rule text or a compliance verdict. It no longer emits fixed generic project rules. Use the current rule text from the parent or `leerness rule list` in the target project and inspect the applicable active rules. Capture large diagnostic logs outside the prompt and report counts, blockers and evidence paths.

The shared policy supplies the generated AGENTS.md entry, workflow/routing guidance, delegation briefs and the optional global Codex adapter. AGENTS.md holds the one full reading paragraph because Leerness serves several agents; CLAUDE.md imports AGENTS.md with an `@AGENTS.md` line that Claude Code expands at launch, and the Cursor rule, the Copilot instructions and the session workflow point to that section, since the same text had been loaded more than once at session start. Minimal mode follows the paragraph directly, so its copy does not send the reader to context-routing.md, which the context budget would otherwise count. The global Codex adapter keeps its copy for Codex modes that do not read AGENTS.md. Existing raw/toggle opt-outs and review feedback contracts remain available. Install/update refreshes managed instructions while preserving custom content and task/rule state through the existing merge mechanism. Existing custom instructions that demand more reading are not silently deleted.

This is guidance, not an access limiter, automatic context freshness validator or proof of agent compliance. The CLI does not automatically assemble a complete delegation packet, filter all harness reads or measure token savings. Existing installed projects and global adapters need their normal explicit update before receiving these instructions. No model calls are needed for the isolated generation, migration and dispatch regressions in `npm run test:context-reading`.

For an older Korean install, migration can encounter the generated "every session" bootstrap and mandatory eleven-document list alongside the newer role-scoped instructions. When those old blocks match the known managed template exactly and the migration backup contains the identical original `AGENTS.md`, the migration leaves the old bytes in that backup and omits the conflicting blocks from the active file. Edited blocks and already-preserved custom text are not inferred to be generated and remain for manual review. This is limited to that exact legacy template; it does not prune arbitrary instructions or prove that an agent follows the newer scope. The installed project must be updated explicitly.

## Current views and size diagnosis

`leerness context current [path] [--task T-0001] [--limit 10] [--json]` reads the canonical tracker and full rules document through checked UTF-8 readers. Without a task selection it returns all nonterminal rows, including unknown statuses, and at most ten terminal references. The reference limit accepts 1–50. Order is last-updated descending, with later canonical row order for ties; it does not imply completion time. Selecting a task returns its full fields even if completed. Totals cover active tracker rows plus indexed retained task metadata when `.leerness/archive/history/index.json` is present. Exact retained-task selection verifies the retained source and row SHA-256 before returning the original fields. Source byte counts and SHA-256 identify the read snapshot, not permanent freshness or verification.

The view is navigation: user-authored current state, explicit read instructions, dependencies, fixed review criteria, open findings and referenced evidence still need the appropriate scoped reads. Task fields and rule text are never silently shortened. The 8 KiB advisory content target reports overflow instead. Missing, malformed, duplicate, unreadable, changing or oversized sources fail visibly. Indexed retained task IDs continue reserving their numbers even after their active row is moved later by a separately approved retention operation. Unindexed arbitrary archive files are not treated as task history.

`leerness context budget [path] --files-only [--json]` measures metadata for twelve named current documents. It neither reads their bodies nor executes handoff or traverses archives. Missing files are listed; unavailable sizes make the total unknown. Initial advisory targets are 8 KiB for each handoff/current-state document and 32 KiB for the named non-rule documents combined. These are byte targets, not token budgets or a reason to remove required content. Existing `context budget` without the flag retains its broader output measurement. Both diagnostics are read-only.

Session close includes the metadata diagnosis and reports at most ten recently updated references for each terminal category, with full counts and canonical lookup instructions. Active/unknown rows remain unabridged. The generated handoff summary has explicit start/end markers. Only that region is refreshed; unmarked legacy history, custom prose and frontmatter are retained. Repeated close does not append another generated block. Ambiguous markers refuse publication. An older document can therefore remain large; the size report makes that visible. The existing current-state auto-line ownership and source-checked publication remain in use.

This first phase performs no archival move, semantic compression, physical compression or deletion, and adds no background service or persisted size cache. Twelve metadata lookups keep each close diagnosis bounded without reading history. CTX-02B provides archive-aware lookup, aggregate counts and historical ID reservation, but retained preview/apply/restore must still precede any historical task move. A smaller derived view alone does not establish token savings, faster review or rule compliance. Test current views with `npm run test:context-current` and indexed retained-task behavior with `npm run test:history-retention`.

Session close now chooses one actionable task for its recommended direction and next exact step. An explicit session-close --task T-ID wins; otherwise numbered entries in the optional owner-priorities block of plan.md take precedence. Without either, it selects the most recently updated in-progress task, then planned, requested or incomplete work. Missing or non-actionable explicit IDs and ambiguous priority markers fail before the handoff changes. The plan is checked again before publication. The JSON nextTask.source field shows how the task was selected. This is navigation, not permission to override task dependencies.

## Indexed retained task history

The development reader recognizes only `.leerness/archive/history/index.json` with schema `leerness.history-index/v1`. Each retained task entry binds a terminal task ID/status/update value to one file under its operation directory plus a full-source SHA-256 and exact raw-row SHA-256. The index is bounded; duplicate IDs, path escape, malformed metadata, conflicting source digests, missing indexes and nonterminal retained tasks fail closed.

Aggregate counts and ID reservation use index metadata without loading retained bodies. `task list --all`, exact `verify-claim`, `memory search`, `memory archive list` and exact `context current --task` can resolve indexed retained rows; exact/body-dependent reads validate the source and row before use. Active and retained copies of the same task ID are treated as an integrity error rather than silently choosing one.

This reader does not move records itself. The explicit [task-history retention commands](history-retention.md) provide selected-row previews, retained originals, restoration and recovery. A pending operation fences ordinary history reads and allocation until the files are consistent. Existing incomplete legacy archives are never converted into trusted records by guessing an empty index. Automatic retention and actual-project rollout remain separate.

Retained IDs and both digest fields must be strings. Numeric task IDs must fit the safe integer range, and allocation refuses an exhausted retained range before editing the active tracker. Merely retaining a completed row does not prove its evidence: claim verification resolves the original row and still checks the referenced implementation.
