# Stored OpenAI response retrieval

`require('leerness/lib/openai-response-retrieval').retrieveOpenAiResponse(requestJson, apiKey)` is an explicit server-side, read-only API. It performs one authenticated GET to `https://api.openai.com:443/v1/responses/<responseId>`. No runtime dependencies or CLI configuration are required.

```js
const { retrieveOpenAiResponse } = require('leerness/lib/openai-response-retrieval');
const observation = await retrieveOpenAiResponse(JSON.stringify({
  responseId: savedResponseId,
  projectId: configuredProjectId,
  organizationId: configuredOrganizationId, // optional; omit when unused
  timeoutMs: 5000,
}), serverSideApiKey);
```

The caller supplies the credential and project explicitly. There is no ambient key/config lookup or configurable host, transport, proxy, CA, HTTP method, or query string. Response IDs use 1–256 ASCII letters/digits/underscore/hyphen; scope IDs use 1–128. These are this adapter's limits, not guarantees about future provider ID formats. Input is strict JSON, at most 4096 UTF-8 bytes; unknown fields and duplicate keys fail before network access. The default total deadline is 5000 ms, configurable from 100 to 15000 ms.

The returned object has schema `leerness.openai-response-retrieval/v1`, `ok`, and **always** `executionBindingVerified:false`, `retryAllowed:false`, `approvalGranted:false`. Success contains `requestedScope` (the caller's selection) and a response projection: `id`, `status`, `model`, `createdAt`, `output`. The ID must match the requested ID. Six statuses are supported: queued, in_progress, completed, failed, cancelled, incomplete. Output item order/types are preserved; tool calls are data and are never executed. Model/status values are provider-reported observations, not an assessment of a reviewer or its independence. Only projection fields are validated, not the complete provider response schema or semantic content.

The response body must be uncompressed JSON with UTF-8 encoding, at most 65536 bytes. Fatal UTF-8 decoding and the existing strict parser reject BOM, duplicate keys, depth over16, more than10000 nodes, or arrays over1000 items. Header size is capped at16384 bytes. The deadline includes DNS/TLS/headers/body and is not reset by incoming bytes. Standard Node TLS certificate/name verification remains enabled. An organization response header, when present alongside an explicit organization, must match; missing headers do not establish account identity. The requested project/organization is not a verified dispatch binding.

Failures return only a fixed `error.code`; credentials, raw network exceptions and provider error bodies are omitted. Codes: `retrieval_input_invalid`, `retrieval_unavailable`, `retrieval_timeout`, `retrieval_incomplete`, `redirect_rejected`, `retrieval_denied`, `response_unavailable`, `retrieval_rate_limited`, `retrieval_http_error`, `response_format_invalid`, `response_too_large`, `response_scope_mismatch`, `response_invalid`. There is no automatic redirect, retry, polling, response creation, cancellation or deletion. A missing/expired/denied response does not prove the original operation never ran.

Successful output can contain sensitive or untrusted model/tool content. The API returns it in memory and does not log or persist it. It must not be treated as executable instructions or automatically attached to a public record. This API neither changes Git refs/RunRecords nor supplies a review recovery handle. Durable authorized dispatch locators, original material/account/attempt binding, receipt/ledger reconstruction, and accepted/final-target gates remain separate work. A caller-selected ID cannot substitute for those proofs, even when retrieval succeeds.

Protocol checked on2026-09-14 against [OpenAI's response retrieval reference](https://developers.openai.com/api/reference/cli/resources/responses/methods/retrieve) and [authentication/scope reference](https://developers.openai.com/api/reference/overview). The adapter requires a retrievable stored response and suitable account permissions; local tests do not establish live account support or retention policy.

`node scripts/openai-response-retrieval-probe.js` runs real loopback TLS tests with an ephemeral certificate generated by OpenSSL (Git for Windows' bundled OpenSSL on this PC). Only the test process redirects the internal Node request to that fixture. It does not contact OpenAI, use real credentials or run coding agents. TLS trust/name rejection, redirects, failures, truncation, size/deadline limits and concurrent calls are exercised. Fixture generation failure is a test failure, not a skip.
