# Installer text preservation

Installation and migration use the shared checked text boundary for
`.gitignore`, `.gitattributes`, `.env.example`, `.env`, README synchronization,
the migration report and nonsecret Leerness configuration. Standalone
`leerness readme sync` uses the same README boundary.

Invalid UTF-8, unsafe targets, oversized input/output or invalid generated
Unicode stop the selected step. They are not silently replaced with different
characters. Valid multilingual text, combining characters and existing UTF-8
signatures are retained. Existing line/key/README merge rules still apply;
the migration report still replaces the previous report. This is not a promise
of exact formatting or preservation of text intentionally regenerated by those
existing policies. Identical output keeps its modification time.

Each read/merge/publication uses a canonical per-file lock and the existing
`managed-text` checked snapshot and publisher, with its 4 MiB limit. A detected
intervening change is refused. Competing content may be retained at a recovery
path named in the error. These checks coordinate cooperating writers and detect
specific external races; they do not prevent every external edit or guarantee
power-loss durability.

## Environment and configuration

Environment merges keep existing key values. A failed environment or config
step stops installation, so later steps cannot overwrite the rejected source.
`--no-env` and minimal mode retain their existing meaning: skip environment
generation. The existing migration of nonsecret settings from an existing
environment file still runs, using the same strict text checks.

Nonsecret migration locks the environment before configuration. It checks the
planned environment edit, saves configuration first, then removes the copied
values from the environment. A config-save failure leaves the source values in
place. If environment publication fails after the copy, the error identifies
the saved configuration; duplicates may remain for recovery. Configuration
retains unrelated keys and its existing explicit-key/secret-filter policy.
Malformed nonempty JSON and non-object JSON now stop the operation instead of
silently resetting settings; empty configuration still initializes normally.
JSON syntax errors do not quote the file's contents. Existing Unix owner-only
environment permission adjustment is retained; Windows validation does not
certify Unix permission behavior.

## Partial work and limits

Errors identify the failed stage and counts of earlier completed core file
steps and selected later text stages. These are execution counts, not counts
of changed files. Earlier changes, backups and unrelated installer effects are
not rolled back. Dry-run keeps its read-only planning behavior. The installer's
no-op decision may skip report generation and does not certify every skipped
file's encoding.

Other JSON/generic writers, release transaction rollback, optional metadata readers, global installers,
language selection and historical text repair remain separate. Byte-valid
mojibake is not repaired or certified meaningful. Existing projects receive
these changes only when they use a version containing them.

Run `npm run test:install-text` for isolated real CLI regressions. Select a
group with `node scripts/install-text-probe.js --match "rejects malformed"`.
See [shared text checks](managed-text-storage.md) and
[instruction generation](generation-text-storage.md).
