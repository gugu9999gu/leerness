# Project Brief

## Project
leerness — AI 코딩 에이전트 운영 레이어 (CLI + MCP)

## Purpose
- 작업 상태, 결정, 교훈, 규칙을 저장소의 `.harness/` 평문 파일에 보존해 세션이나 에이전트가 바뀌어도 맥락을 이어갈 수 있게 한다.
- 완료 주장을 파일, 테스트, 실행 결과 같은 증거와 대조하고 `handoff → work → verify → session close` 흐름으로 신뢰할 수 있는 작업 마감을 만든다.
- Claude Code, Codex, Cursor 등 특정 공급자나 프로그래밍 언어에 종속되지 않는 공통 운영 표면을 CLI와 MCP로 제공한다.
- 기본은 협조형으로 동작하되, 필요한 팀에는 enforce 모드와 CI 검사를 통해 같은 규칙을 강제 가능한 가드레일로 제공한다.

## Users
- 장기 또는 다중 세션 프로젝트에서 AI 코딩 에이전트와 협업하는 개발자와 팀
- 에이전트 교체에도 유지되는 저장소 로컬 상태와 명시적인 인수인계가 필요한 유지보수자
- 구조화된 CLI/MCP 결과를 사용해 작업 상태, 검증, 감사 흐름을 자동화하는 도구 작성자

## Success Criteria
- 새 세션이나 새 에이전트가 한 번의 handoff로 현재 목표, 완료·진행·차단 상태, 다음 행동을 복원할 수 있다.
- 완료된 작업은 `verify-claim`으로 관련 파일과 검증 증거를 확인할 수 있고, 증거가 없거나 모순된 완료 주장은 통과하지 않는다.
- 운영 상태는 사람이 읽고 버전 관리할 수 있는 평문 파일로 남으며, CLI와 MCP가 동일한 핵심 워크플로를 제공한다.
- 자동화용 명령은 일관된 종료 코드와 구조화된 결과를 제공하고, drift·secret·encoding 검사가 문제를 명시적으로 보고한다.
- 설치 기준은 Node.js 18 이상, 런타임 의존성 0개, install script 0개, offline-first를 유지하며 Windows를 포함한 지원 환경에서 검증된다.
- 릴리스 주장은 selftest, E2E, 클린룸 평가 등 재현 가능한 증거에 연결되고, 알려진 한계와 실패는 숨기지 않고 기록한다.

## Boundaries
- leerness는 애플리케이션 코드를 작성하거나 코딩 에이전트를 대체하지 않고, 에이전트가 수행하는 작업의 운영 흐름을 보완한다.
- 휴리스틱 검증은 비즈니스 로직의 의미적 정확성을 증명하지 않으며, 테스트 품질·전문 보안 도구·사람의 검토를 대체하지 않는다.
